Summary

Truncating text with an ellipsis hides content from everyone who can't hover over it, specifically keyboard-only users. We propose a solution—a component that keeps the full value reachable by keyboard, screen reader, and pointer. Plain text that overflows its container gets a button element that appears similarly to the way the CSS ellipsis would show. This Reveal Button component will show the full text in a tooltip. CSS detects the overflow without measuring layout in JavaScript, so the page never has to watch for resizes… at least not for this.

1 · Architecture

Three layers, two ways to reveal

Throughout, my-design-system stands for your design system package: its stylesheets under styles/, with its components, modifiers, and utilities beside them. my-app stands for any app that uses it. If your styles ship as a separate package (say my-design-system-styles), the CSS layer moves there unchanged. The examples are written as Ember (Glimmer templates and element modifiers) with tippy.js for tooltips, but the technique is CSS first: the overflow decision, in most instances, needs no JavaScript at all, and the two primitives map onto concepts every component framework has. The code samples in this document are illustrative, not drop-in: adapt the names, imports, and tooltip library to your own stack.

The CSS, overall, owns the overflow decision. Two primitives sit on top of it: the <Truncation> component, for plain text, and the truncationHost modifier, for elements that are already interactive. Both rely on applyTooltip, a thin wrapper around tippy.js; section 7 lists exactly what it borrows from tippy. The app never measures anything itself. It picks a primitive per value, in the template that renders it.

The same two primitives in other frameworks

Nothing here depends on Ember beyond syntax. A component renders markup from arguments; a modifier receives an element that something else rendered and attaches behavior to it, with a teardown. Most frameworks name both.

2 · Variations

Variations and how they are applied

The rule is decided by what the value is, not by where it sits. Plain text gets a Reveal Button. An element that already takes focus becomes a Reveal Host, because a button nested inside a link or a select trigger would be a nested interactive element. Every variation below is one of these two, or builds on one of them.

3 · The CSS

The overflow probe, the keyframe, and the style query

The trick is that an overflow: hidden box is a scroll container, and a scroll timeline is only active while its container has something to scroll. .c-truncation__plain is that box. It names its timeline --c-truncation, and timeline-scope on the wrapper hoists the name, so the wrapper's own animation can bind to it.

  1. While the text fits, the timeline is inactive, so the animation applies nothing. --c-truncation-overflowing stays unset, and the plain text shows.
  2. Once the text overflows, the timeline turns active. The keyframe, which is the same at from and to, sets --c-truncation-overflowing: 1 on the wrapper.
  3. Every element is a style container for its descendants, so @container style(--c-truncation-overflowing: 1) now matches the wrapper's children. The plain text collapses to an absolutely positioned, zero-height, hidden box, and the overflow branch (the faded copy plus the button) displays.
  4. The plain text keeps the wrapper's full inline size, set by inset-inline: 0, so it still overflows and keeps the timeline active. Because it measures without the button's 22px, showing the button can never change the answer, so the two states don't flicker back and forth.

The button is calc(1lh - 2 × 4px) tall, so it fits inside one line of text together with its 2px ring at a 2px offset. Revealing never changes a row's height, and the ring is never clipped by the cell's overflow: hidden. The overflow branch reserves the same 4px as end padding.

4 · The component

The markup for each state

<Truncation> is a template-only component that takes one argument, @text. It renders the value twice. The plain copy is real text that screen readers read while it fits. The overflow copy is aria-hidden, so while the value is trimmed, the full value reaches assistive technology through the button's aria-label and its tooltip instead. The hidden plain copy is visibility: hidden, which takes it out of the accessibility tree, so the value is never read twice.

  • hideOnClick=false keeps the tooltip open when the button is clicked. There is no pinned state. The option name is tippy's, passed straight through.
  • The button is the design system's own Button, so it is a tab stop exactly when it is visible. In the fits state it is display: none and not focusable.
  • ...attributes lands on the wrapper, so consumers add classes and test selectors there (class, data-test-*).

5 · The modifier

An interactive element reveals its own text

A link or a select trigger can't hold a Reveal Button, because that would be a control inside a control. It keeps a native ellipsis (.c-truncation-host), and the element itself carries the tooltip. The modifier is a thin call to applyTooltip with showWhen: 'overflowing'.

With showWhen: 'overflowing', the tooltip decides when it shows rather than when it is attached. tippy's onShow hook returns false to cancel. So a host that fits never shows a tooltip, a host that clips always does, and nothing has to watch for resizes in between.

"Clipped" is measured on the element's clips. A clip is the host itself, or any descendant marked data-truncation-clip, or a clip inside the host's <label> (for a file upload). The measurement compares a text Range's width with the clip's content box, both read from getBoundingClientRect, so zoom and transforms cancel out, and a fraction-of-a-pixel overflow still counts. This file is plain DOM: it knows nothing about tippy.

Every tooltip, whether a Reveal Button's or a host's, goes through the same applyTooltip. It enforces the trigger rules:

  • The trigger must be focusable and must not be natively disabled; otherwise a development assert fires.
  • The tooltip mounts beside its trigger.
  • It is positioned with Popper's fixed strategy, so table cells and scroll containers can't clip it.
  • Esc dismisses it.
  • A host's tooltip is aria-hidden, because it only repeats the host's own text.

6 · Reveal Hosts

One modifier, any element that already takes focus

A Reveal Host is whatever element receives focus. Its visible text keeps a native ellipsis, and the modifier on the focusable element reveals that text while it is clipped. What changes from element to element is only where the clip is, and whether the element opens a popup of its own.

A link

The simplest host: the link is the focusable element and its own text is the clip. The text argument is optional here, since the link's text is what would be read anyway; passing it skips reading the DOM.

A button with an icon

The button's box also holds the icon, so the button itself is not the clip: its label is. Mark the label data-truncation-clip and leave out the text argument, and the tooltip reads the label when it shows. The icon keeps its size because the button holds it as a separate flex item with flex-shrink: 0 (see the rules).

A file upload

A styled file upload is usually a <label> that wraps a visually hidden <input type="file">. The input is what takes focus, so it hosts the tooltip, but the file name it should reveal sits beside it in the label. truncationClips finds clips through input.labels, so no wiring is needed for the measurement. The pointer, though, hovers the label rather than the hidden input, so the tooltip listens on both and is positioned against the label.

With a file chosen, a name like my-long-breakable-file-name-for-the-quarterly-report-final-v2.pdf clips in the label, and focusing the input shows it whole. Pressing Enter or Space opens the picker, and hideWhenExpanded hides the tooltip as it opens.

A select trigger

A custom select is a button that opens a listbox. The selected value is the clip; the button is the host. While the listbox is open the trigger carries aria-expanded="true", so the tooltip neither shows nor stays up over the options.

A native <select> draws its selected value itself, outside the DOM, so there is no text to measure. Use a button-based trigger like the one above when the selected value can clip.

A menu button with two lines

A profile chip often stacks a display name over an email, and either line can clip on its own. Mark the wrapper as the clip and make each line a block: clippedTextLines returns one entry per block child, and revealHostContent turns them into one tooltip row each. No text argument is passed, so the tooltip always matches what is rendered.

7 · tippy.js

What comes from the tooltip library, and what doesn't

Two of the three layers know nothing about tippy.js: the CSS, and utils/text-overflow.ts, which is plain DOM. Everything that touches tippy sits in utils/tooltips.ts: applyTooltip, showAsRevealHost, and the two plugins. A few option names also pass straight through from callers (hideOnClick, triggerTarget, getReferenceClientRect, aria, placement). Replacing tippy means rewriting that one file against the same TooltipOpts, and renaming those options if the new library spells them differently.

8 · Locked hosts

Optional: a control that stays reachable and says why it is unavailable

This is an extension, not part of the core. Some controls are temporarily unavailable and should explain why. Such a control stays focusable with aria-disabled="true" instead of disabled, so its tooltip is still reachable from the keyboard. reason is read when the tooltip shows, so locking and unlocking need no re-attach. When the value is clipped too, formatReason joins the two as "value: reason". If your design system has no such controls, leave both options out; showAsRevealHost then behaves exactly as in section 5.

  • The reason is also the button's description (aria-describedby), so a screen reader hears it without the tooltip, which stays aria-hidden like any Reveal Host's.
  • Translate the separator in formatReason; not every language joins with a colon.

9 · Consumers

How an app picks a variation

An app never measures anything. It picks a primitive per value, in the template that renders it. The examples below are common places where a long value meets a narrow box.

Table cells: text and links

A text cell wraps its value in a <Truncation>. A cell whose value is a link makes the link a Reveal Host instead; when the link stacks several lines, each line is its own clip.

Link or text, per row

The same value can be a link in one row and plain text in another, for example when the user can't open that record. The variation follows the element: a Reveal Host when it links, a Reveal Button when it doesn't. An identifier that sits next to its name stays whole; only the name truncates.

Inside a link or not: two variations for one value

A component that shows an identifier beside a title is sometimes rendered inside a link and sometimes not. Inside a link, the title can only clip, because the link is the host; outside one, it gets its own Reveal Button.

Reusing the parts

A cell that stands for several values reuses the Reveal Button's classes for a button that is always present, because there are always more values to list. A label that puts a name inside a sentence splits its translated copy around a placeholder character. That way the name can sit on its own line with a <Truncation>, in any language's word order.

10 · Testing

Waiting for the timeline, and asserting the state

The scroll timeline resolves on the animation frame after the framework has settled, so tests await two more frames. The plain copy stays laid out (zero height, hidden) while overflowing, so a visibility check can't tell the states apart. The page object asks whether the Reveal Button renders any box instead. Some test runners scale their container down (Ember's does, to 50% by default), so tests assert states and relative measurements, never absolute pixel widths. The helpers below use Ember's test helpers and page objects; the two ideas carry over to any runner.

11 · Rules

Rules that keep it correct

  1. Pick the variation by the element, not the place. Plain text gets <Truncation>; a link, button, trigger, menu button, or file upload gets {{truncationHost}}. Never put a Reveal Button inside a link or button.
  2. Tooltip triggers are focusable. Attach tooltips to interactive elements only. A control that must explain itself while unavailable uses aria-disabled, never disabled; applyTooltip asserts this in development.
  3. One tooltip per trigger. A second source only swaps content, with a warning. If a host needs to say more, give it a reason; don't add a second tooltip.
  4. No mouse-only title. Converting a value means removing its title; the reveal replaces it.
  5. IDs stay whole unless they are the link. An ID that shares a line with its name never truncates; only the name does. A standalone ID truncates only where it is itself the link.
  6. Leave room for the ring. The 4px --c-truncation-focus-ring budget sits inside the value's space, because cells clip with no padding.
  7. The fallback wraps. Without scroll-driven animations, values wrap in full instead of truncating, so nothing is lost.
  8. An icon beside truncating text keeps its size. An icon whose <svg> is itself a flex item next to clipped text gets flex-shrink: 0, or the default flex-shrink: 1 squeezes it to a sliver. An icon inside a button or link is already held by that wrapper's minimum width. Test it by comparing the icon's width to its height with a very long value; the ratio holds under the test runner's scaling.
  9. A tooltip on a labeled trigger mounts beside the label. Put it next to the <label>, not inside it, so a click in the tooltip doesn't activate the label's control (a file name's tooltip would otherwise reopen the file picker).
  10. An open cell lifts while its tooltip is open. A table cell holding an open tooltip lifts above its neighbors and a sticky header, so their shadows can't erase its border. While scrolled under the header, it paints over the header until the tooltip closes; that is an accepted trade-off.
  11. Rows act only through explicit controls. A table row takes no click of its own: an expand button expands it and a link opens it. So a Reveal Button is never nested in an interactive row, and expandable rows use the same cells as flat rows.
  12. Multi-part hosts mark their clips. Put data-truncation-clip on each part that can clip, or on a wrapper whose lines are blocks, and let revealHostContent build one row per line.
Screen readers announce a Reveal Button's value twice: once as its name, once through tippy's aria-describedby. This is an accepted trade-off; a library that lets you skip the description avoids it. A Reveal Host's tooltip is aria-hidden, because the host's accessible name is already the full text.
