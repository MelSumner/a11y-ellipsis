Summary

Truncating text with an ellipsis hides content from everyone who can't hover over it. This component keeps the full value reachable by keyboard, screen reader and pointer. Plain text that overflows its container gets a button element that appears similarly to the way the CSS ellipsis would show. This Reveal Button will show the full text in a tooltip. CSS detects the overflow without measuring layout in JavaScript, so the page never has to watch for resizes.

1 · ARCHITECTURE

Three layers, two ways to reveal

Throughout, ui-kit-styles stands for your stylesheet package, ui-kit for your component library, and app for any site that uses them. The examples are Ember (Glimmer templates, modifiers) with tippy.js for tooltips, but the CSS technique works with any framework. The code samples in this document are illustrative, not drop-in: adapt the names, imports and tooltip library to your own stack.

ui-kit-styles owns the overflow decision. ui-kit owns two primitives: the <Truncation> component, for plain text, and the truncationHost modifier, for elements that are already interactive. Both rely on applyTooltip, the shared tippy wrapper. The app never measures anything itself. It picks a primitive per value, in the template that renders it.

2 · FLAVORS

Variations and how they are applied

The rule is decided by what the value is, not by where it sits. Plain text gets a Reveal Button. An element that already takes focus becomes a Reveal Host, because a button nested inside a link or a select trigger would be a nested interactive element. Everything below is one of these two forms, or a variant of one of them.

3 · THE CSS

The overflow probe, the keyframe and the style query

The trick is that an overflow: hidden box is a scroll container, and a scroll timeline is only active while its container has something to scroll. .c-truncation__plain is that box. It names its timeline --c-truncation, and timeline-scope on the wrapper hoists the name, so the wrapper's own animation can bind to it.

  1. While the text fits, the timeline is inactive, so the animation applies nothing. --c-truncation-overflowing stays unset, and the plain text shows.
  2. Once the text overflows, the timeline turns active. The keyframe, which is the same at from and to, sets --c-truncation-overflowing: 1 on the wrapper.
  3. Every element is a style container for its descendants, so @container style(--c-truncation-overflowing: 1) now matches the wrapper's children. The plain text collapses to an absolutely positioned, zero-height, hidden box, and the overflow branch (the faded copy plus the button) displays.
  4. The plain text keeps the wrapper's full inline size, set by inset-inline: 0, so it still overflows and keeps the timeline active. Because it measures without the button's 22px, showing the button can never change the answer, so the two states don't flicker back and forth.

The button is calc(1lh - 2 × 4px) tall, so it fits inside one line of text together with its 2px ring at a 2px offset. Revealing never changes a row's height, and the ring is never clipped by the cell's overflow: hidden. The overflow branch reserves the same 4px as end padding.

4 · THE COMPONENT

The markup the CSS swaps between

<Truncation> is a template-only component that takes one argument, @text. It renders the value twice. The plain copy is real text that screen readers read while it fits. The overflow copy is aria-hidden, so while the value is trimmed, the full value reaches assistive technology through the button's aria-label and its tooltip instead. The hidden plain copy is visibility: hidden, which takes it out of the accessibility tree, so the value is never read twice.

  • hideOnClick=false keeps the tooltip open when the button is clicked. There is no pinned state.
  • The button is a real ui-kit Button, so it is a tab stop exactly when it is visible. In the fits state it is display: none and not focusable.
  • ...attributes lands on the wrapper, so consumers add classes and test selectors there (class, data-test-*).
5 · THE MODIFIER AND REVEAL HOSTS

An interactive element reveals its own text

A link or a select trigger can't hold a Reveal Button, because that would be a control inside a control. It keeps a native ellipsis (.c-truncation-host), and the element itself carries the tooltip. The modifier is a thin call to applyTooltip with showWhen: 'overflowing'.

With showWhen: 'overflowing', the tooltip decides when it shows rather than when it is attached. tippy's onShow returns false to cancel. So a host that fits never shows a tooltip, a host that clips always does, and nothing has to watch for resizes in between.

"Clipped" is measured on the element's clips. A clip is the host itself, or any descendant marked data-truncation-clip, or a clip inside the host's <label> (for a file input). The measurement compares a text Range's width with the clip's content box, both read from getBoundingClientRect, so zoom and transforms cancel out, and a fraction-of-a-pixel overflow still counts.

Every tooltip, whether a Reveal Button's or a host's, goes through the same applyTooltip. It enforces the trigger rules:

  • The trigger must be focusable and must not be natively disabled; otherwise a development assert fires.
  • The tooltip mounts beside its trigger.
  • It is positioned with Popper's fixed strategy, so table cells and scroll containers can't clip it.
  • Escape dismisses it.
  • A host's tooltip is aria-hidden, because it only repeats the host's own text.
6 · LOCKED HOSTS

A reachable disabled control that says why

A locked control stays focusable: it uses aria-disabled, not disabled, so its tooltip is still reachable from the keyboard. reason is read when the tooltip shows, so locking and unlocking need no re-attach. When the value is clipped too, formatReason joins the two as "value: reason", using a translated separator.

7 · CONSUMERS

How an app picks a form

An app never measures anything. It picks a primitive per value, in the template that renders it. The examples below are common places where a long value meets a narrow box.

Table cells: text and links

A text cell wraps its value in a <Truncation>. A cell whose value is a link makes the link a Reveal Host instead; when the link stacks several lines, each line is its own clip.

Link or text, per row

The same value can be a link in one row and plain text in another, for example when the user can't open that record. The form follows the element: a Reveal Host when it links, a Reveal Button when it doesn't. An identifier that sits next to its name stays whole; only the name truncates.

Inside a link or not: two forms for one value

Reusing the parts

A cell that stands for several values reuses the Reveal Button's classes for a button that is always present, because there are always more values to list. A label that puts a name inside a sentence splits its translated copy around a placeholder character. That way the name can sit on its own line with a <Truncation>, in any language's word order.

8 · TESTING

Waiting for the timeline, and asserting the state

The scroll timeline resolves on the animation frame after settled() has returned, so tests await two more frames. The plain copy stays laid out (zero height, hidden) while overflowing, so isVisible can't tell the states apart. The page object asks whether the Reveal Button renders any box instead. Ember's test container is scaled down (to 50% by default), so tests assert states and relative measurements, never absolute pixel widths.

9 · RULES

Rules that keep it correct

  • Pick the variation by the element, not the place. Plain text gets <Truncation>; a link, trigger, menu button or input gets {{truncationHost}}. Never put a Reveal Button inside a link or button.
  • Tooltip triggers are focusable. Attach tooltips to interactive elements only. A locked control uses aria-disabled, never disabled; applyTooltip asserts this in development.
  • One tooltip per trigger. A second source only swaps content, with a warning. Give a host its reason through reason; don't add a second tooltip.
  • No mouse-only title. Converting a value means removing its title; the reveal replaces it.
  • IDs stay whole unless they are the link. An ID that shares a line with its name never truncates; only the name does. A standalone ID truncates only where it is itself the link.
  • Leave room for the ring. The 4px --c-truncation-focus-ring budget sits inside the value's space, because cells clip with no padding.
  • The fallback wraps. Without scroll-driven animations, values wrap in full instead of truncating, so nothing is lost.
  • An icon beside truncating text keeps its size. An icon whose <svg> is itself a flex item next to clipped text gets flex-shrink: 0, or the default flex-shrink: 1 squeezes it to a sliver. An icon inside a button or link is already held by that wrapper's minimum width. Test it by comparing the icon's width to its height with a very long value; the ratio holds under the test runner's scaling.
  • A tooltip on a labelled trigger mounts beside the label. applyTooltip puts it next to the <label>, not inside it, so a click in the tooltip doesn't activate the label's control (a file name's tooltip would otherwise reopen the file picker).
  • An open cell lifts while its tooltip is open. A table cell holding an open tooltip lifts above its neighbours and a sticky header, so their shadows can't erase its border. While scrolled under the header, it paints over the header until the tooltip closes; that is an accepted trade-off.
  • Rows act only through their Row Controls. A table row takes no click of its own: its Expand Toggle expands it and its Open Trigger opens it, each named from the row header's value. So a Reveal Button is never nested in an interactive row, and expandable rows use the same cells as flat rows.
  • Multi-part hosts mark their clips. Put data-truncation-clip on each part that can clip, and let revealHostContent build one row per line.
Screen readers announce a Reveal Button's value twice: once as its name, once through tippy's aria-describedby. This is an accepted trade-off. A Reveal Host's tooltip is aria-hidden, because the host's accessible name is already the full text.
